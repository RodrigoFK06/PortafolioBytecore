Especificación Técnica del Proyecto

Documento de arquitectura y stack tecnológico — Proyecto Shali / Árkós

⚙ Stack Tecnológico de Producción

Capa Tecnología Versión Justificación
Framework Frontend Next.js (App Router + React Server Components) 16.0.10 RSC elimina JS innecesario en cliente; streaming con Suspense para TTFB <200ms. Partial Prerendering (PPR) para rutas híbridas estáticas/dinámicas.
UI / Estilos TailwindCSS v4 + Radix UI Latest Utilidad-first con zero-runtime CSS; Radix provee primitivos accesibles (WAI-ARIA) para modals, calendarios y dropdowns sin depender de librerías pesadas.
Autenticación Supabase Auth + @supabase/ssr 0.8.x Auth basado en JWT con PKCE flow; cookies HttpOnly SSR-safe para proteger tokens. Soporta MFA, OAuth social y magic links out-of-the-box.
Base de Datos PostgreSQL (Supabase managed) 15+ RLS (Row Level Security) nativo para multi-tenancy seguro. Funciones PL/pgSQL para cálculos de comisiones en servidor. Realtime subscriptions vía WebSockets para cambios de calendario en vivo.
Validación Zod + React Hook Form Latest Schemas tipados end-to-end (client → server actions → DB). Validación isomorfa: el mismo schema Zod protege formularios y API routes, eliminando vectores de inyección.
Hosting / CDN Vercel (Edge Network) — CDN global con edge functions en 30+ regiones. Automatic ISR (Incremental Static Regeneration) para cachear páginas de propiedades. CI/CD integrado con preview deploys por cada push.

🏗 Arquitectura del Sistema

Capa de Presentación

  • • React Server Components (RSC) para renderizado en servidor sin hidratación innecesaria
  • • Client Components solo para interactividad (calendarios, formularios, filtros dinámicos)
  • • Streaming SSR con Suspense boundaries para carga progresiva
  • • Service Worker + Manifest para instalación PWA nativa

Capa de Lógica / API

  • • Next.js Server Actions para mutaciones tipadas sin API boilerplate
  • • Route Handlers (app/api/*) para webhooks e integraciones
  • • Middleware edge para auth guards, rate limiting y redirecciones por rol
  • • Validación Zod en cada boundary (form → action → DB)

Capa de Datos

  • • PostgreSQL con Row Level Security (RLS) — cada usuario solo ve sus datos permitidos
  • • Supabase Realtime para sincronización de calendarios entre dispositivos
  • • Funciones PL/pgSQL para cálculos de comisiones atómicos
  • • Políticas de seguridad a nivel de fila para RBAC sin lógica adicional en backend

📦 Detalle de Ingeniería por Módulo

1. Motor de Búsqueda y Filtrado Avanzado

Implementación

  • • Queries optimizadas con índices GIN/GiST en PostgreSQL para búsquedas por rango de fechas y geolocalización
  • • Filtros composables en cliente con URL state sync (useSearchParams + nuqs)
  • • Debounce inteligente + startTransition para UX sin bloqueos
  • • Server-side pagination con cursores para datasets grandes

Performance

  • • ISR para páginas de listado (revalidación cada 60s)
  • • Optimistic UI en favoritos y acciones rápidas
  • • Image optimization con next/image (WebP/AVIF auto)
  • • Lazy loading de cards con Intersection Observer

2. Módulo Financiero y Comisiones

Implementación

  • • Cálculos de comisiones ejecutados como funciones PL/pgSQL en transacciones atómicas (ACID compliance)
  • • Schemas Zod dedicados para cada tipo de operación financiera
  • • Tablas de auditoría con triggers automáticos para trazabilidad completa
  • • Separación de concerns: lógica financiera aislada en server actions

Reportes

  • • Dashboard con métricas en tiempo real via Supabase Realtime
  • • Exportación a CSV/PDF con generación server-side
  • • Filtros por período, propiedad y agente vendedor
  • • Vistas materializadas para reportes agregados sin afectar queries transaccionales

3. Calendarios Avanzados con Sincronización en Tiempo Real

Implementación

  • • Componentes Radix UI con calendario interactivo y selección de rangos
  • • Supabase Realtime (WebSockets) para reflejar bloqueos/reservas instantáneamente entre usuarios
  • • Locking optimista con detección de conflictos en reservas simultáneas
  • • Vista master consolidada + vistas individuales por propiedad

UX

  • • Drag-and-drop para ajustar reservas
  • • Color coding por estado (disponible, reservado, bloqueado, mantenimiento)
  • • Tooltips con detalle de cada reserva sin navegación extra
  • • Responsive: vista semanal en mobile, mensual en desktop

4. Sistema de Roles y Seguridad (RBAC)

Implementación

  • • RBAC implementado a nivel de base de datos con PostgreSQL RLS policies
  • • Supabase Auth JWT con claims personalizados por rol (admin, vendedor, viewer)
  • • Middleware Next.js en edge para validar roles antes de renderizar rutas protegidas
  • • Principio de mínimo privilegio: cada rol solo accede a lo estrictamente necesario

Auditoría

  • • Log de acciones con timestamp, usuario, IP y detalle del cambio
  • • Triggers PostgreSQL para auditoría automática de tablas sensibles
  • • Vista de actividad reciente para administradores
  • • Protección CSRF + rate limiting en Server Actions

5. Progressive Web App (PWA)

Implementación

  • • Service Worker con estrategia cache-first para assets estáticos y network-first para datos
  • • Web App Manifest completo con splash screens, iconos adaptativos y tema de color
  • • Prompt de instalación personalizado con A2HS (Add to Home Screen)
  • • Offline fallback para consultar calendarios y propiedades en caché

Performance targets

  • • Lighthouse PWA score ≥ 95
  • • LCP (Largest Contentful Paint) < 1.5s
  • • CLS (Cumulative Layout Shift) < 0.05
  • • FID (First Input Delay) < 50ms

CI/CD & Despliegue
